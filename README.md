# 踏频 Stridebeat · 跑步音乐工坊

项目仓库：[Drinkerdrink/stridebeat](https://github.com/Drinkerdrink/stridebeat)。在 GitHub 点击 **Code → Download ZIP** 可下载整个项目。

把喜欢的歌曲变成适合跑步的节奏。支持单曲、批量制作、原曲和成品试听、点声音量调整、输出文件夹选择，以及拖动排序后合并歌单。

**这是独立分享版，不需要原作者的账号或网站权限。** 页面、处理代码和音频组件都在本文件夹内，无需 `npm install`，无需 API 密钥。运行环境安装好后，本地制作音频不需要联网。

## 一、最快启动方式（Windows）

1. 解压整个 ZIP，保留 `Stridebeat` 文件夹内的目录结构。
2. 电脑需要安装 **Node.js 18 或以上**，或者 **Python 3.9 或以上**，二选一即可。
   - Node.js 官方下载：<https://nodejs.org/>
   - Python 官方下载：<https://www.python.org/downloads/>
3. 双击 **`启动网站.bat`**。脚本会优先使用 Node.js，找不到时尝试 Python 3，并打开默认浏览器。
4. 如果浏览器没有自动打开，请手动访问：**<http://127.0.0.1:4173>**。
5. 使用期间保持启动窗口打开；结束后，在窗口中按 `Ctrl+C` 停止服务。

**不要直接双击 `dist/index.html`。** 网站使用 JavaScript 模块和后台音频处理线程，通过 `file://` 打开可能无法运行，必须按上面的方法启动。

启动脚本不会安装软件，不会请求管理员权限。若找不到运行环境，会提示安装。包内没有捆绑 Node.js 或 Python 运行时。

## 二、手动启动（Windows / macOS / Linux）

在本文件夹打开终端，任选一种方式：

```bash
# Node.js
node server.mjs

# Python 3；部分 Windows 环境需使用 py -3 或 python
python3 server.py
```

随后在浏览器打开 `http://127.0.0.1:4173`。命令后添加 `--open` 可尝试自动打开默认浏览器。

如果 4173 端口被占用，可以换一个端口：

```bash
node server.mjs --port 4174
# 或
python3 server.py --port 4174
```

此时访问 `http://127.0.0.1:4174`。本地服务只监听当前电脑，不会自动向局域网或互联网开放。

## 三、使用方法

### 1. 添加和试听输入歌曲

- 选择“单曲制作”或“批量制作”。
- 点击左侧“添加歌曲”，或把歌曲拖入输入区。
- 添加后自动识别原曲 BPM；左侧播放器可试听原曲。
- 原曲 BPM 由低频鼓点和其他频段的节奏共同估计。存在节奏冲突或接近识别边界时，会提示核对。
- 如识别不准确，可直接修改每首歌的 BPM，或用“½ 半拍 / ×2 倍拍”切换数拍方式。比如 84 和 168 可表示同一首歌的不同节拍层级；制作跑步节奏时通常先试听接近目标步频的选择。单曲模式通过“制作这首”选择要处理的歌曲。

### 2. 设置步频和点声

- 目标步频可选 **170、180、190、200 步／分钟**，也可选择“自定义”，输入 **160–210 之间的整数**。超出范围时不能生成。
- 点声音量可调 **0–300%**；设为 0 即不叠加点声。
- 超过 100% 可让点声更突出；混音会适当降低音乐，保留峰值余量，避免破音。300% 的点声与音乐比例为原 100% 的三倍，不代表设备总音量提高三倍。
- “试听点声”可预听节拍音色；成品响度会随音乐内容和防破音处理变化。
- 变速时保留原来的音高；唱词的速度和歌曲时长会随变速改变。

### 3. 选择输出文件夹

- 点击“选择输出文件夹”，在浏览器弹出的窗口中选中本地文件夹并授权。
- 可以启用“生成后自动保存”，并选择 **MP3、WAV 或两种格式**。
- 同名文件会自动加编号，避免覆盖已有文件。
- 浏览器只允许页面显示所选文件夹名称，不一定提供完整磁盘路径；文件夹授权仅保留在当前页面会话。
- 文件夹选择需要浏览器支持相关接口，并在 `localhost` / `127.0.0.1` 或 HTTPS 环境运行。若按钮不可用或授权失败，直接使用输出列表里的下载按钮即可，保存位置由浏览器下载设置决定。

### 4. 生成和试听输出

- 点击“一键批量生成”或“生成选中单曲”。
- 处理完成后，右侧输出列表显示成品，可试听并下载 **MP3（192 kbps）** 或 **WAV（44.1 kHz、双声道、16 位 PCM）**。
- 原始歌曲文件不会被修改。清空输入列表后，右侧已生成的成品仍会保留。
- 修改步频或点声音量不会改变已有成品；重新生成后，相应的输出条目才会更新。

### 5. 排序和合并

- 在右侧输出列表中勾选要参与合并的歌曲，至少两首。
- 在下方“歌单时间轴”中左右拖动彩色歌曲模块调整顺序；拖到边缘会自动横向滚动。也可点击模块上的左右箭头，或让模块获得焦点后按键盘左右方向键。按 Esc 可取消当前拖拽。右侧输出列表顺序会同步更新，也仍可用列表的上下箭头排序。
- 在相邻歌曲之间的“静音过渡”模块输入 **0–60 秒**，支持 **0.1 秒精度**，默认 0 秒。模块配色区分歌曲与过渡，并标出歌曲的起止时间。
- 过渡时间跟随它前面的歌曲移动；最后一首之后不添加静音。总时长包含这些间隔。模块宽度为示意，准确时间以标注为准。
- 时间轴下方的“歌单试听”可直接播放、暂停并拖动进度条跳到任意位置，不需要先合并。试听包含设置的静音过渡；只勾选一首时也可试听。
- 调整顺序、勾选或过渡后，试听会自动更新并回到开头；点击播放后即可试听新编排。播放原曲或单曲时，歌单试听会自动暂停，避免声音重叠。
- 点击“合并为一个音频”，按当前时间轴顺序及静音过渡生成完整音频。
- 合并结果可试听，并下载 MP3 或 WAV；如已启用自动保存，也会保存到所选文件夹。
- MP3 和 WAV 都包含设置好的静音过渡，间隔内没有音乐或点声。不进行交叉淡化；各单曲保留各自生成时的步频设置。修改勾选、顺序或过渡时间后，请重新合并。

**刷新、关闭页面或离开网站会丢失尚未保存的结果，请先下载或自动保存。**

## 四、文件格式与限制

- 可选择 MP3、WAV、OGG、FLAC、M4A 等音频文件；能否解码取决于浏览器。
- 单首时长为 **8 秒至 8 分钟**，单个文件最大 **80 MB**。
- 输入列表最多 **12 首**，输入歌曲总时长最多 **40 分钟**。
- 自动节拍识别是估计，可能出现半拍或倍拍。现场演奏、自由节奏或速度变化较大的音乐，可能无法和固定点声全程贴合。
- 大幅变速可能影响音色细节；请先试听再用于完整跑步歌单。
- 音频处理消耗当前设备的 CPU 和内存，大批量或较长歌曲需要更多时间。

## 五、如何分享给别人

### 方式 A：发送这个文件夹或 ZIP

把整个 `Stridebeat` 文件夹压缩后发送，接收者解压并按“最快启动方式”运行即可。无需你提供账号或授权原网站访问。

### 方式 B：部署成可访问的网址

这是纯静态网站，可以托管到支持静态文件的 HTTPS 网站服务：

1. 将 **`dist` 文件夹里的内容**作为网站发布内容，确保网站根目录有 `index.html`。
2. 不需要构建命令，也不需要安装项目依赖。
3. 保留 `dist/vendor`、所有 `.js` 和 `.css` 文件的相对路径；JavaScript 文件需以 JavaScript MIME 类型提供。
4. 开启 HTTPS，以便使用浏览器的本地文件夹访问功能。
5. 如果自行设置内容安全策略，需要允许本网站的模块与 Worker，以及 `blob:` 音频播放。

`server.mjs` 和 `server.py` 用于本机启动，公开静态托管时只上传 `dist` 即可。独立分享包不包含原网站的托管标识、账户凭据或 Git 历史，也不会更改原网站的访问权限。

## 六、隐私与目录结构

音频在访问者自己的浏览器中解码、变速、混音和导出；本地服务只提供网页文件，没有歌曲上传接口。包内的试用音乐由代码合成，不含原用户的歌曲、测试音频或个人生成结果。

```text
Stridebeat/
├─ README.md                使用、分享与部署说明
├─ 启动网站.bat              Windows 启动入口
├─ server.mjs               Node.js 本地服务
├─ server.py                Python 3 备用本地服务
├─ package.json             可选的 npm 启动和检查命令
├─ THIRD_PARTY_NOTICES.md    第三方组件和源码说明
├─ dist/                    可独立部署的全部网页文件
│  ├─ index.html
│  ├─ batch.js / batch.css
│  ├─ style.css
│  ├─ audio-engine.js / audio-worker.js
│  ├─ playlist.js / timeline.js / playlist-preview.js
│  ├─ merge-engine.js / merge-worker.js
│  ├─ file-output.js
│  └─ vendor/               随包提供的音频组件和许可证
├─ third-party-source/      第三方组件的可读源码及相关文件
└─ tests/                   可选开发检查，不影响普通使用
```

## 七、常见问题

**双击启动脚本后提示找不到 Node.js / Python。** 先安装其中一种运行环境，再重新打开启动脚本。Windows 中仅存在 Python 商店入口时，仍需完成 Python 安装。

**页面打不开或提示端口被占用。** 保持服务窗口打开，确认使用窗口打印的地址；尝试 `--port 4174`。

**选不了输出文件夹。** 这项能力取决于浏览器与安全上下文。不要使用 `file://`；本机使用 `127.0.0.1`，公开部署使用 HTTPS。不支持时仍可下载音频。

**某首歌导入失败。** 可尝试换成 MP3 或 WAV，并确认文件可正常播放、时长和大小未超限。

**修改设置后输出听起来没变。** 已生成的条目保留旧设置，需要再次点击生成，右侧会显示这首成品实际使用的步频与点声音量。

**合并按钮不可用。** 先在右侧生成并勾选至少两首歌曲。输入列表里的原曲不会直接参与合并。

## 八、开发检查与第三方组件

可选：安装 Node.js 后在本目录运行以下命令，不需要 `npm install`：

```bash
node tests/audio.test.mjs
node tests/merge.test.mjs
node tests/file-output.test.mjs
```

检查会生成 `test-output` 目录，只包含合成测试音频。目录选择测试采用模拟目录；实际文件夹授权需要使用者在浏览器中完成。

网站使用 **SoundTouchJS 0.3.0** 和 **lamejs 1.2.1**。第三方组件保留各自许可证，详细说明见 `THIRD_PARTY_NOTICES.md`、`dist/credits.html` 和 `dist/vendor`。再次分发时请保留相关许可证与源码文件。
